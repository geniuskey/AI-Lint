# 룰 카탈로그

문서 검사 룰 31개와 추적성 룰 6개. 지적마다 붙는 `docsUrl`이 이 페이지의 해당 룰 항목을 가리킵니다.

카탈로그의 단일 진실 공급원은 `packages/rules/src/catalog/meta.ts`입니다. 규칙셋 검증, `GET /v1/rules`, LLM 프롬프트 생성이 모두 이 표를 참조합니다. 실행 중인 백엔드에서 그대로 받아볼 수도 있습니다.

```bash
curl -s $BACKEND/v1/rules -H "x-ai-lint-token: $SERVICE_TOKEN" | jq '.rules[] | {id, name, axis, llm}'
```

**LLM 판정** 룰은 모델이 판단합니다. `useLlm: false`로 요청하거나 쿼터가 소진되면 이 룰들은 돌지 않습니다. **결정적 판정** 룰은 LLM 없이도 항상 돕니다.

**옵션**은 [규칙셋](#규칙셋으로-조정하기)에서 룰별로 덮어쓸 수 있습니다.

STR004, STR005, STR011, STR014는 전부 "내용이 아예 추출되지 않는다"는 뜻입니다. 표가 이미지면 그 안의 숫자는 검색에도 답변에도 절대 등장하지 않습니다. 읽기 불편한 것과 읽히지 않는 것은 다른 문제라 error로 둡니다.
:::

### STR001 · heading-hierarchy-skip {#str001}

`warning` · 결정적 판정

제목 블록을 순서대로 훑으면서 레벨이 2 이상 뛰는 지점을 찾습니다. h2 다음에 h4가 오면 걸립니다.

> 제목 계층은 AI가 문서를 청크로 나눌 때 쓰는 뼈대입니다. 레벨을 건너뛰면 상위-하위 관계가 끊겨 잘못된 단위로 잘립니다.

**고치기** — 건너뛴 레벨을 채우거나 제목 레벨을 한 단계 올립니다. 지적에는 `h3: <제목>` 형태의 수정 제안이 함께 나옵니다.

### STR002 · no-headings {#str002}

`error` · 결정적 판정 · `minChars: 800`

제목 블록이 하나도 없고 본문 총 길이가 `minChars`를 넘을 때 한 번 지적합니다. 짧은 메모는 제목이 없어도 문제가 아니라서 길이 조건을 둡니다.

> 제목이 없으면 문서 전체가 하나의 덩어리로 취급됩니다. AI는 질문과 관련된 부분만 골라내지 못하고 문서 전체를 통째로 읽거나 임의의 길이로 잘라야 합니다.

**고치기** — 내용을 주제 단위로 끊고 각 덩어리에 제목을 붙입니다.

### STR003 · section-too-long {#str003}

`warning` · 결정적 판정 · `maxSectionChars: 1500`

섹션 하나(제목 하나와 다음 제목 직전까지의 블록들)의 글자 수가 `maxSectionChars`를 넘으면 그 섹션마다 지적합니다.

> 한 섹션이 1500자를 넘으면 검색 단위 하나에 여러 주제가 섞입니다. AI가 이 청크를 인용하면 질문과 무관한 내용까지 함께 딸려옵니다.

**고치기** — 하위 제목으로 쪼갭니다. 청크 크기를 더 작게 가져가는 검색 파이프라인이라면 `maxSectionChars`를 900 정도로 낮추세요.

### STR004 · table-as-image {#str004}

`error` · 결정적 판정

OCR 텍스트가 없는 이미지 블록 중, 앞 두 블록이나 뒤 한 블록에 `표·차트·그래프·다이어그램·아키텍처·플로우·table·chart·diagram` 같은 말이 있는 것을 찾습니다. 같은 섹션에 진짜 표 블록이 이미 있으면 지적하지 않습니다 — 그림과 표를 함께 둔 정상적인 경우입니다.

> 이미지 속 표는 AI에게 존재하지 않는 데이터입니다. 주변 문장은 이 그림을 참조하는데 정작 값은 읽을 수 없어, 답변에서 근거가 빠지거나 지어내게 됩니다.

**고치기** — 이미지는 그대로 두고, 같은 내용을 표 블록으로도 옮겨 적습니다. 그림은 사람이 보고 표는 기계가 읽습니다.

### STR005 · image-missing-alt {#str005}

`error` · 결정적 판정

이미지 블록의 대체 텍스트와 캡션이 **둘 다** 쓸모없을 때 지적합니다. 다음은 설명으로 치지 않습니다.

- 3자 미만
- 파일명 (`.png`, `.jpg`, `.gif`, `.svg`, `.webp`, `.bmp`로 끝나는 문자열)
- `image1`, `screenshot`, `캡처`, `그림 2` 같은 자리표시자

> AI는 이미지를 읽지 못합니다. 설명이 없으면 이 이미지가 담은 정보는 문서에 존재하지 않는 것과 같습니다.

**고치기** — 이미지가 무엇을 보여주는지 한 문장으로 적습니다. "결제 승인 요청부터 정산까지의 흐름도"처럼요.

### STR006 · code-block-no-language {#str006}

`info` · 결정적 판정 · `minLines: 3`

언어가 지정되지 않은 코드블록 중 `minLines` 줄 이상인 것을 찾습니다. 한두 줄짜리는 어차피 인라인 코드와 다르지 않아 넘어갑니다.

> 언어 표시가 없으면 AI는 이 블록이 코드인지 로그인지 설정 파일인지 구분하지 못합니다. 코드로 인용해야 할 내용을 산문처럼 요약해버립니다.

**고치기** — 코드블록에 언어를 지정합니다. 로그나 출력이라면 `text`, `log`라도 붙이는 편이 낫습니다.

### STR007 · vague-link-text {#str007}

`warning` · 결정적 판정

링크 텍스트가 다음 중 하나면 지적합니다.

- 여기, 이곳, 링크, 클릭, 여기를 클릭, 자세히, 자세히 보기, 더보기, 바로가기, 참고, 참조
- here, click here, link, this, this link, read more, more, see, see here
- URL 그대로 (`https://…`)

> AI는 링크를 따라가지 않습니다. 링크 텍스트가 곧 대상 문서에 대한 유일한 설명이므로, "여기"는 아무 정보도 전달하지 못합니다.

**고치기** — 대상 문서의 제목을 링크 텍스트로 씁니다. 확장이 링크 대상의 제목을 알아낸 경우 그 제목이 수정 제안에 그대로 들어갑니다.

### STR008 · layout-table {#str008}

`info` · 결정적 판정

어댑터가 레이아웃용으로 판정한 표이거나, 헤더가 없고 셀이 두 개 이하인 표를 찾습니다.

> 표는 AI에게 "행과 열에 의미가 있다"는 신호입니다. 배치용 표는 없는 관계를 있는 것처럼 읽히게 만들어 잘못된 대응을 만들어냅니다.

**고치기** — 배치가 목적이라면 표를 걷어내고 문단이나 목록으로 바꿉니다.

### STR009 · table-no-header {#str009}

`warning` · 결정적 판정

레이아웃 표가 아니고, 헤더 행이 없으며, 2행 이상인 표를 찾습니다.

> 헤더가 없으면 각 열이 무엇인지 알 수 없습니다. AI는 표를 행 단위로 인용하면서 값이 어떤 항목의 값인지 붙이지 못합니다.

**고치기** — 첫 행을 헤더로 지정하거나 열 이름 행을 새로 추가합니다.

### STR010 · deep-nesting {#str010}

`info` · 결정적 판정 · `maxDepth: 3`

목록 블록의 중첩 깊이가 `maxDepth`를 넘을 때 지적합니다.

> 깊은 중첩은 텍스트로 펼쳐지는 순간 계층 정보를 잃습니다. AI는 4단계 아래 항목이 어느 상위 항목에 속하는지 되짚지 못합니다.

**고치기** — 하위 항목을 별도 섹션이나 표로 승격합니다.

### STR011 · attachment-only {#str011}

`error` · 결정적 판정 · `minChars: 200`

본문 총 길이가 `minChars` 미만인데 첨부파일 링크가 하나 이상 있을 때 지적합니다.

> 첨부파일은 별도로 열어야 읽을 수 있습니다. 페이지만 검색되는 환경에서 이 문서는 제목만 있고 알맹이가 없는 문서로 취급됩니다.

**고치기** — 첨부의 핵심 내용을 본문에 옮겨 적고, 첨부는 원본 보관용으로 남깁니다. 첨부 자체를 검사하려면 [데스크톱 앱](/guide/desktop)에 넣으세요.

### STR012 · unrendered-macro {#str012}

`warning` · 결정적 판정

내용을 담는 매크로인데 렌더된 텍스트가 비어 있는 경우를 찾습니다. 대상 매크로는 `include`, `excerpt-include`, `excerpt`, `multimedia`, `viewxls`, `viewpdf`, `viewdoc`, `viewppt`, `widget`, `iframe`, `html`, `drawio`, `gliffy`입니다.

> 매크로가 화면에만 그려지고 저장 형식에는 참조만 남으면, 문서를 수집하는 쪽에서는 빈 자리로 보입니다. 그 자리의 내용은 검색에 잡히지 않습니다.

**고치기** — 핵심 내용을 본문 텍스트로도 남기거나, 매크로 대신 실제 내용을 붙여넣습니다.

### STR013 · emphasis-as-heading {#str013}

`warning` · 결정적 판정

굵게·큰 글씨만으로 제목을 흉내 낸 문단을 찾습니다. 어댑터가 문단 블록에 표시를 붙입니다.

> 글자 모양만 바꾼 제목은 문서 구조에 남지 않습니다. 추출 도구가 섹션 경계를 찾지 못해 여러 주제가 한 청크로 묶이고, 인용할 때 어느 절의 내용인지 붙일 수 없습니다.

**고치기** — 제목 1~3 스타일을 적용합니다.

### STR014 · scanned-pdf {#str014}

`error` · 결정적 판정

PDF에서 블록이 하나도 추출되지 않았을 때 문서 단위로 한 번 지적합니다. 텍스트 레이어 없이 이미지만 들어 있는 스캔본입니다.

> 그림만 있는 PDF는 검색도 인용도 되지 않습니다. AI는 이 문서의 내용을 한 글자도 읽지 못합니다.

**고치기** — OCR로 텍스트 레이어를 넣거나, 원본 문서를 PDF로 다시 내보냅니다.

## 맥락 자립성 (CTX) {#맥락-자립성-ctx}

가중치 **0.45**. 아홉 개 전부 **LLM 판정**입니다.

문서가 자기 안에서 닫혀 있는지를 봅니다. 검색이 이 문서 한 조각을 가져왔을 때, 그것만으로 답이 되는가 하는 질문입니다.

| ID | 이름 | 심각도 | 적용 대상 |
|---|---|---|---|
| [CTX001](#ctx001) | dangling-reference | error | 전체 |
| [CTX002](#ctx002) | undefined-term | warning | 전체 |
| [CTX003](#ctx003) | missing-purpose | warning | 전체 |
| [CTX004](#ctx004) | ambiguous-actor | warning | 전체 |
| [CTX005](#ctx005) | unresolved-pronoun | warning | 전체 |
| [CTX006](#ctx006) | relative-time | info | 전체 |
| [CTX007](#ctx007) | decision-without-rationale | warning | `design`, `meeting-notes`, `requirement` |
| [CTX008](#ctx008) | section-topic-drift | warning | 전체 |
| [CTX009](#ctx009) | external-assumption | info | 전체 |

::: warning LLM 지적은 검증을 통과한 것만 남습니다
모델은 판정할 때 근거가 된 본문 문장을 함께 내야 하고, 그 문장이 실제 본문에 존재하는지 대조합니다. 없으면 그 지적은 버려지고 `stats.llmFindingsRejected`에 집계됩니다. 확신도 하한도 함께 적용됩니다.
:::

문서가 길면 여러 구간으로 나눠 보내지만, 각 구간마다 문서 제목·유형·전체 목차·요약을 함께 넘깁니다. 자립성 판정은 문서 전체의 골격을 알아야 가능하기 때문입니다. 규칙셋에서 꺼둔 룰과 이 문서 유형에 적용되지 않는 룰은 프롬프트에 아예 실리지 않습니다.

### CTX001 · dangling-reference {#ctx001}

`error` · LLM 판정

"지난번 논의대로", "위 표 참고"처럼 문서 안에서 해소되지 않는 참조를 찾습니다. 가리키는 대상이 같은 문서에 없으면, 이 조각만 검색된 사람은 무슨 말인지 복원할 수 없습니다.

**고치기** — 참조 대상을 문서 안에 적거나, 대상 문서를 제목과 함께 링크합니다.

### CTX002 · undefined-term {#ctx002}

`warning` · LLM 판정

정의 없이 등장하는 약어, 사내 은어, 코드네임을 찾습니다.

**고치기** — 처음 나올 때 한 번 풀어 씁니다. 자주 쓰는 용어라면 용어집 문서(`reference` 유형)를 만들고 링크하세요.

### CTX003 · missing-purpose {#ctx003}

`warning` · LLM 판정

문서의 목적과 범위가 도입부에 명시되지 않은 경우를 찾습니다.

**고치기** — 맨 앞에 이 문서가 무엇을 다루고 무엇을 다루지 않는지 적습니다. [META002](#meta002)와 함께 걸리는 일이 많습니다.

### CTX004 · ambiguous-actor {#ctx004}

`warning` · LLM 판정

주어가 생략되어 누가 하는 일인지 알 수 없는 문장을 찾습니다. "배포 후 확인한다"에서 확인하는 주체가 누구인지 문서 어디에도 없는 경우입니다.

**고치기** — 팀·역할·시스템 중 무엇이 주체인지 문장에 넣습니다.

### CTX005 · unresolved-pronoun {#ctx005}

`warning` · LLM 판정

"이것", "해당 방식" 같은 지시대명사가 가리키는 대상이 같은 섹션 안에 없는 경우를 찾습니다. 섹션 경계가 곧 청크 경계라서, 앞 섹션에 있는 대상은 없는 것과 같습니다.

**고치기** — 대명사를 실제 이름으로 바꿉니다.

### CTX006 · relative-time {#ctx006}

`info` · LLM 판정

"현재", "최근", "다음 주"처럼 기준 시점이 없는 시간 표현을 찾습니다.

**고치기** — 절대 날짜로 바꿉니다. 문서가 오래될수록 이 표현들은 조용히 틀린 말이 됩니다.

### CTX007 · decision-without-rationale {#ctx007}

`warning` · LLM 판정 · `design`, `meeting-notes`, `requirement`에만 적용

결정은 적혀 있는데 근거나 검토한 대안이 없는 경우를 찾습니다.

적용 대상이 제한된 유일한 룰입니다. 회의록에 결정 근거가 없다는 지적은 타당하지만, API 문서에 같은 지적을 하면 소음이기 때문입니다.

**고치기** — 왜 그렇게 정했는지, 무엇을 대신 검토했는지 한 단락 적습니다. 나중에 이 결정을 뒤집을지 판단하는 사람에게 필요한 정보입니다.

### CTX008 · section-topic-drift {#ctx008}

`warning` · LLM 판정

섹션 제목과 실제 내용이 어긋나는 경우를 찾습니다.

**고치기** — 제목을 내용에 맞추거나 섹션을 쪼갭니다. 검색은 제목을 믿고 청크를 고르므로, 어긋난 제목은 잘못된 청크를 불러옵니다.

### CTX009 · external-assumption {#ctx009}

`info` · LLM 판정

문서 밖에 있는 전제를 알아야만 성립하는 문장을 찾습니다. 그 팀에서 일하는 사람만 아는 관행 같은 것들입니다.

**고치기** — 전제를 문서 안에 적거나, 전제를 설명한 문서를 링크합니다.

## 메타데이터 · 최신성 (META) {#메타데이터-최신성-meta}

가중치 **0.20**.

| ID | 이름 | 심각도 | 판정 | 기본 옵션 |
|---|---|---|---|---|
| [META001](#meta001) | title-not-descriptive | warning | 결정적 + LLM | |
| [META002](#meta002) | missing-summary | warning | 결정적 | `minChars: 1200` |
| [META003](#meta003) | no-labels | info | 결정적 | |
| [META004](#meta004) | no-owner | info | 결정적 | |
| [META005](#meta005) | stale-document | info | 결정적 | `staleMonths: 12` |
| [META006](#meta006) | broken-link | warning | 결정적 | |
| [META007](#meta007) | missing-required-section | error | 결정적 + LLM | |
| [META008](#meta008) | draft-marker | warning | 결정적 | |

META001과 META007은 양쪽입니다. 결정적 검사가 명백한 경우를 먼저 걸러내고, LLM이 본문을 읽어야 알 수 있는 경우를 마저 봅니다. `useLlm: false`로 검사해도 결정적 부분은 그대로 돕니다.

### META001 · title-not-descriptive {#meta001}

`warning` · 결정적 + LLM 판정

결정적 검사는 세 가지를 봅니다.

- 회의록, 메모, 임시, 초안, notes, draft, untitled 같은 일반명사가 제목 전체인 경우
- 복사본·사본·백업·`copy of`·`old`·`deprecated` 흔적이 남은 제목
- 5자 미만의 제목

LLM은 여기에 더해 제목이 실제 본문 내용을 대변하는지 봅니다.

> 제목은 검색 결과에서 이 문서를 고를지 말지를 결정하는 유일한 단서입니다. 제목이 내용을 대변하지 못하면 관련 있는 문서가 후보에서 먼저 탈락합니다.

**고치기** — 무엇에 대한 문서인지 드러나게 씁니다. `[2026-07-15] 결제 모듈 아키텍처 리뷰`처럼요.

### META002 · missing-summary {#meta002}

`warning` · 결정적 판정 · `minChars: 1200`

본문이 `minChars`를 넘는데 요약이 없을 때 지적합니다. 다음 중 하나면 요약이 있는 것으로 봅니다.

- 첫 두 섹션의 제목에 요약·개요·정리·배경·목적·TL;DR·summary·overview·abstract·purpose가 들어 있음
- 제목 없이 문서 맨 앞에 놓인 도입 문단이 100자 이상

> 요약이 있으면 AI가 문서 전체를 읽지 않고도 이 문서가 질문과 관련 있는지 판단합니다. 요약이 없으면 긴 문서일수록 검색에서 통째로 밀려납니다.

**고치기** — 문서 맨 앞에 무엇을 다루고 누가 읽어야 하는지 3줄 이내로 적습니다.

### META003 · no-labels {#meta003}

`info` · 결정적 판정

라벨이 하나도 없을 때 지적합니다.

> 라벨은 문서를 주제·팀·수명주기로 묶는 유일한 구조화 신호입니다. 라벨이 없으면 검색 범위를 좁히지 못해 무관한 문서와 같은 후보군에 섞입니다.

**고치기** — 주제·시스템·문서 유형 라벨을 최소 두 개 붙입니다.

### META004 · no-owner {#meta004}

`info` · 결정적 판정

문서 메타데이터에 소유자가 없고, 본문에도 `담당자:`, `작성자:`, `owner:` 같은 표기가 없을 때 지적합니다. 코드블록 안의 표기는 세지 않습니다.

> 내용이 낡았을 때 누구에게 확인해야 하는지 알 수 없습니다. 소유자가 없는 문서는 검증할 방법이 없어 신뢰도를 낮게 잡아야 합니다.

**고치기** — 문서 상단에 `담당자: 홍길동` 형태로 적거나 페이지 소유자를 지정합니다.

### META005 · stale-document {#meta005}

`info` · 결정적 판정 · `staleMonths: 12`

최종 수정 시각으로부터 `staleMonths`개월이 지났으면 지적합니다. 한 달은 30일로 셉니다. 수정 시각이 없거나 파싱되지 않으면 넘어갑니다.

> 오래된 문서와 최신 문서가 같은 무게로 검색되면, AI는 이미 폐기된 결정을 현행 사실처럼 인용합니다.

**고치기** — 내용을 검토해 갱신하거나, 유효하지 않다면 상단에 보관·대체 문서 안내를 남깁니다. 문서 수명이 짧은 팀이라면 `staleMonths`를 6으로 낮추세요.

### META006 · broken-link {#meta006}

`warning` · 결정적 판정

IR의 링크 중 상태가 `broken`인 것을 지적합니다. 백엔드는 링크를 직접 열어보지 않습니다. Confluence 확장이 [사용자 세션으로 확인](/guide/extension#링크-검사)해서 상태를 채워 보냅니다. 권한이 없어 403이 나는 것과 문서가 사라진 404를 구분하려면 그래야 합니다.

> 깨진 링크는 근거가 사라졌다는 신호입니다. 이 문서를 인용하는 답변은 확인할 수 없는 출처를 달게 됩니다.

**고치기** — 옮겨간 문서로 링크를 갱신하거나, 사라졌다면 해당 문장을 정리합니다.

### META007 · missing-required-section {#meta007}

`error` · 결정적 + LLM 판정

문서 유형별로 있어야 할 섹션이 제목에 보이지 않을 때 지적합니다. 제목 비교는 공백을 지우고 소문자로 맞춘 뒤 부분 일치로 합니다. 동의어 중 하나만 맞아도 있는 것으로 봅니다.

| 유형 | 필요한 섹션 |
|---|---|
| `meeting-notes` | 일시 · 참석자 · 결정사항 · 액션아이템 |
| `requirement` | 목적/범위 · 요구사항 · 수용 기준 |
| `design` | 배경/문제 · 결정/설계 · 대안/트레이드오프 |
| `guide` | 대상 독자 · 전제조건 · 단계/절차 |
| `api-doc` | 엔드포인트 · 파라미터/요청 · 응답 · 예시 |
| `troubleshooting` | 증상 · 원인 · 해결 |
| `reference` | 정의/용어 |
| `unknown` | 없음 |

각 항목에는 한국어·영어 동의어가 등록되어 있습니다. 예를 들어 `design`의 "대안"은 트레이드오프, 검토한 대안, alternatives, tradeoffs로도 인정됩니다.

LLM은 섹션 이름이 동의어 목록에 없는 말로 붙어 있어도 그 내용이 실제로 있는지 봅니다.

> 같은 유형의 문서가 같은 골격을 가지면 AI가 여러 문서를 가로질러 같은 항목을 비교할 수 있습니다. 골격이 어긋난 문서는 그 비교에서 빠집니다.

**고치기** — 빠진 섹션을 추가합니다. 유형 자동 분류가 틀렸다면 `POST /v1/doctype-overrides`로 지정하세요.

### META008 · draft-marker {#meta008}

`warning` · 결정적 판정

TBD, TODO, FIXME, XXX, 작성중, 추후 작성, 미정, `???` 같은 미완성 표식을 찾습니다. 코드블록 안은 보지 않습니다 — 코드의 TODO는 코드에 대한 메모지 문서의 미완성 표식이 아닙니다. `TODO`만 적힌 제목도 섹션 이름으로 보고 넘어갑니다.

> AI는 미완성 표식을 걸러내지 않고 그 주변 문장을 확정된 내용처럼 인용합니다. 채워지지 않은 자리가 사실로 둔갑합니다.

**고치기** — 내용을 채우거나, 아직 정해지지 않았다면 언제 누가 정하는지 적습니다.

## 문서간 추적성 (TRC) {#문서간-추적성-trc}

**문서 점수에 들어가지 않습니다.** `RULE_META`에 없고 `POST /v1/trace/analyze`의 별도 리포트로만 나갑니다. 코퍼스 상태에 따라 판정이 달라지는 룰을 단일 문서 점수에 섞으면, 남이 문서를 안 올렸다는 이유로 내 문서 등급이 떨어지기 때문입니다.

| ID | 심각도 | 메시지 |
|---|---|---|
| [TRC001](#trc001) | error | 정의되지 않은 식별자를 참조합니다 |
| [TRC002](#trc002) | warning | 설계 문서가 요구사항을 참조하지 않습니다 |
| [TRC003](#trc003) | warning | 요구사항에 연결된 테스트가 없습니다 |
| [TRC004](#trc004) | error | 같은 식별자를 두 문서가 정의합니다 |
| [TRC005](#trc005) | info | 링크 대상 문서가 인덱스에 없습니다 |
| [TRC006](#trc006) | error | 같은 식별자에 대한 서술이 서로 어긋납니다 |

이 룰들은 규칙셋으로 켜고 끄지 않습니다. `POST /v1/trace/analyze`의 `useLlm`만 TRC006에 영향을 줍니다.

### TRC001 · 정의되지 않은 식별자를 참조 {#trc001}

`error` · 결정적 판정

참조는 있는데 그 식별자를 정의하는 문서가 인덱스에 없습니다.

정말 없는 것일 수도, 아직 검사하지 않아 인덱스에 안 들어온 것일 수도 있습니다. 인덱스는 `POST /v1/lint`의 부수 효과로만 쌓이기 때문입니다.

**고치기** — 원본 문서를 검사해 인덱스에 넣거나, 참조를 고칩니다.

### TRC002 · 설계 문서가 요구사항을 참조하지 않음 {#trc002}

`warning` · 결정적 판정

`design` 유형 문서에 requirement 종류의 식별자가 하나도 없습니다.

**고치기** — 이 설계가 어느 요구사항에서 나왔는지 본문에 식별자로 적습니다.

### TRC003 · 요구사항에 연결된 테스트가 없음 {#trc003}

`warning` · 결정적 판정

어떤 요구사항을 참조하는 문서들 중 test 종류의 식별자를 가진 것이 하나도 없습니다. 테스트 문서가 요구사항을 참조하는 실제 관행을 따른 판정입니다.

**고치기** — 그 요구사항을 검증하는 테스트 문서에 요구사항 식별자를 적습니다.

### TRC004 · 같은 식별자를 두 문서가 정의 {#trc004}

`error` · 결정적 판정

같은 식별자를 정의하는 문서가 둘 이상입니다. 제목이나 제목 블록에 식별자가 나오면 정의로 봅니다.

**고치기** — 하나를 정본으로 정하고 나머지는 참조로 바꿉니다.

### TRC005 · 링크 대상 문서가 인덱스에 없음 {#trc005}

`info` · 결정적 판정

내부 링크의 대상 URI가 코퍼스에 없습니다. [META006](#meta006)과 달리 링크가 살아 있는지를 보는 것이 아니라, 대상 문서가 검사된 적 있는지를 봅니다.

**고치기** — 대상 문서를 검사해 인덱스에 넣습니다.

### TRC006 · 같은 식별자에 대한 서술이 어긋남 {#trc006}

`error` · LLM 판정

같은 식별자를 다루는 두 문서가 서로 다른 말을 합니다. 수치, 조건, 책임 주체가 실제로 어긋날 때만 보고합니다. 표현만 다르고 뜻이 같은 경우, 한쪽에만 있는 내용은 상충이 아닙니다.

같은 식별자를 공유하는 문서 쌍만 후보가 되고, 공유 식별자가 많은 순으로 상위 `maxPairs`(기본 20)개만 실제로 대조합니다. 모델에는 발췌만 보내고, 양쪽에서 인용한 문장이 실제 발췌에 있는지 대조해 없으면 버립니다.

**고치기** — 어느 쪽이 맞는지 정하고 나머지를 갱신합니다.

자세한 동작은 [문서간 추적성](/guide/traceability)을 보세요.

## 점수 계산

축마다 100점에서 시작해 지적마다 깎입니다.

| 심각도 | 감점 |
|---|---|
| error | 15 |
| warning | 6 |
| info | 2 |

같은 룰이 **4번째부터**는 1점만 깎습니다. 이미지 40장에 alt가 없다고 그 하나가 점수를 독점하면, 정작 심각한 다른 문제가 점수에 드러나지 않습니다.

```
총점 = 구조 × 0.35 + 맥락 × 0.45 + 메타데이터 × 0.20
```

| 등급 | 총점 |
|---|---|
| A | 90 이상 |
| B | 75 이상 |
| C | 60 이상 |
| D | 그 미만 |

## 규칙셋으로 조정하기

룰별로 끄거나, 심각도를 바꾸거나, 옵션을 덮어씁니다.

```json
{
  "id": "engineering",
  "version": 3,
  "rules": {
    "STR006": { "enabled": false },
    "STR003": { "enabled": true, "severity": "error", "options": { "maxSectionChars": 900 } },
    "META005": { "enabled": true, "severity": "warning", "options": { "staleMonths": 6 } }
  }
}
```

알 수 없는 룰 ID가 들어 있으면 로드가 거부됩니다. 오타 난 규칙셋이 조용히 아무것도 안 하는 상황을 막기 위한 것입니다.

`GET /v1/rulesets`로 목록을, `GET /v1/rulesets/:id`로 내용을 확인합니다.
